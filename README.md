# Coin Surfer

바이낸스 **USDⓈ-M 선물** 시세를 이용해 **거래량 급등 종목**을 찾아 투자하는 대시보드입니다.
**계정별로 독립 운영**되며, 마스터는 전 계정을 한눈에 관리할 수 있습니다.

- 실시간 가격 표시 (호가 스트림)
- 1분봉 거래량 **z-score + 배수 + RSI + 24h 변동** 기준 급등 탐지
- 자동 매수 → **익절 +10% / 손절 −5%** 청산 (수익·손절 기준은 설정 창에서 자유롭게 변경)
- 값은 **매수 체결가(진입가) 기준**으로 계산
- 계정별 설정·포트폴리오 분리, 마스터 전체 로그 열람
- API 키 연결 시 실제 주문 가능 (테스트넷/실계정, 주문 시뮬레이션 지원)

## 빠른 시작

```bash
npm install
npm run up        # 빌드 + 백그라운드 실행 → http://localhost:8787
```

`npm run up` 으로 띄운 서버는 **터미널을 닫아도 계속 실행**됩니다.

| 명령어 | 설명 |
|---|---|
| `npm run up` | 빌드 후 백그라운드로 서버 실행 |
| `npm run down` | 서버 중지 (graceful → 필요 시 강제) |
| `npm run restart` | 재시작 |
| `npm run status` | 실행 상태 확인 (PID / 포트 / 로그) |
| `npm run logs` | 로그 실시간 보기 (`tail -f`) |
| `npm start` | 빌드 + **포그라운드** 실행 (Ctrl+C 로 종료) |
| `npm run dev` | 개발 모드 — 백엔드 `:8787` + 프론트 `:5173`, 코드 수정 시 자동 반영 |
| `npm test` | 테스트 555개 실행 |

> **왜 `npm run up` 을 쓰나요?** — `node src/index.js &` 처럼 일반 백그라운드로 띄우면
> 띄운 터미널 세션이 정리될 때 프로세스도 함께 종료됩니다.
> `npm run up` 은 `detached + unref` 로 실행해 부모 프로세스(1)로 재부모되므로
> 세션과 무관하게 생존합니다. 로그에는 `logs/server.log` 로 남습니다.

기타 명령:

```bash
CS_TOKEN=<토큰> npm run inspect         # 현재 계정 상태 출력
CS_TOKEN=<토큰> npm run inspect <계정ID> # 특정 계정 출력
CS_TOKEN=<토큰> npm run watch           # 실시간 상태 관찰
```

토큰 발급: `curl -s -X POST localhost:8787/api/auth/login -H 'Content-Type: application/json' -d '{"name":"...","password":"..."}'`

> Node 20 이상 필요. 시세 조회는 API 키 없이 가능하지만, 대시보드 사용에는 로그인이 필요합니다.

## 계정별 운영

### 처음 실행하기

1. 브라우저에서 `http://localhost:8787` 접속 → **마스터 계정 만들기** 화면
2. 이름(기본 `master`) + 비밀번호(8자 이상) 입력
3. 기존 단일 계정 데이터가 있으면 마스터의 `기본` 계정으로 자동 승계

### 로그인

이름 + 비밀번호로 로그인합니다. 세션은 7일간 유지됩니다.
로그인 5회 연속 실패 시 1분간 차단됩니다.

### 거래 계정

- 사용자마다 `기본` 거래 계정이 자동 생성됩니다 (설정·포트폴리오·API 키·로그 분리).
- 헤더의 계정 선택기로 전환합니다. 마스터는 전 계정을 `이름 (소유자)` 형태로 봅니다.
- 마스터는 거래계정 탭에서 계정 추가·정지·재개·이름 변경·삭제를 할 수 있습니다.
- 보유 포지션이 있는 계정은 삭제되지 않습니다 (먼저 전량 청산).

### 마스터 패널 (♛ 마스터 버튼)

| 탭 | 내용 |

| 전체 현황 | 전 계정의 모드·자산·손익·보유·후보를 한 표로 |
| 거래계정 | 생성·정지·이름 변경·삭제 |

| 기능 | 내용 |
|---|---|
| 만들기 | 이름·비밀번호(8자 이상)·권한(일반/마스터), 기본 거래계정 자동 생성 |

## 동작 흐름

```
① 유니버스 로드      REST /fapi/v1/exchangeInfo  → 거래 가능한 USDT 퍼펙추얼 종목
② 히스토리 시드      REST /fapi/v1/klines (1m)   → 거래대금 상위 N종의 1분봉 40개
③ 실시간 가격        WS  @bookTicker            → 추적 종목의 실시간 호가 (bid/ask)
                     (무응답 시) WS @trade       → 체결가
                     (무응답 시) REST 폴링        → 분봉 종가
④ 24h 통계           REST /fapi/v1/ticker/24hr  → 24h 거래대금 / 변동률
⑤ 1분봉 폴링         REST /fapi/v1/klines (1m)   → 확정봉 적재 → z-score 계산
⑥ 스캔              임계값 통과 종목 점수순 정렬 → 상위 10종목
⑦ 자동 매수          빈 슬롯만큼 상위 후보부터 가상 매수
⑧ 청산 판정          1초마다 보유 포지션 현재가 반영 → 익절/손절/트레일링/시간
```

### 급등 판정식

단일 1분봉의 스파이크는 노이즈가 커서, **최근 구간의 평균**으로 판정합니다.

```
recentAvg = 최근 R분(기본 3분)의 평균 분당 거래대금
baseAvg   = 그 이전 L분(기본 30분)의 평균 분당 거래대금

z     = (recentAvg - baseAvg) / max(std(baseAvg), baseAvg × 0.2)
ratio = recentAvg / baseAvg
```

두 조건을 **모두** 만족하고 유동성 기준(최소 분당/24h 거래대금)을 통과하면 급등으로 인정합니다.

선정 점수 = `z × 1.0 + (ratio − 1) × 0.35 + |24h 변동률| × 0.05`

> 진행 중인 1분봉은 판정에서 제외합니다(부분 값이라 평균을 왜곡).
> 대신 UI에 `↗ pace`(분당 환산) 로 실시간 힌트를 표시합니다.

### 24시간 변동률 진입 조건

거래량 급등 종목이라도 **24시간 변동률이 마이너스면 진입하지 않습니다.**

```
24h 변동률 ≥ 0%  → 진입 허용
24h 변동률 < 0%  → 진입 차단
```

하락 추세에서 거래량이 터지는 경우는 대개 **탈락 돌파(bear trap)** 나 **하락 추세 속 일시적 반등**이라,
추격 매수하면 손절을 맞을 확률이 높습니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| 24시간 변동 필터 | ON | 끄면 제한 없이 진입 |
| 최소 24시간 변동률 | 0 % | `-3` 으로 낮추면 완만한 하락은 허용, `-100` 이면 사실상 제한 없음 |

> **진입만 막고 청산은 막지 않습니다.**
> 이미 보유한 포지션은 이 조건과 무관하게 익절/손절/트레일링/시간 청산이 정상 동작합니다.
> 그렇지 않으면 하락 추세에서 손절조차 되지 않아 포지션이 갇힙니다.
>
> 검증은 `Portfolio.checkEntryGate()` (진입) 와 `Portfolio.checkExit()` (청산) 가
> 완전히 분리된 경로임을 테스트로 확인합니다.

차단 사유는 화면에 그대로 표시됩니다:

```
24시간 변동 -9.27% < 0% (진입 금지 설정)
```

후보가 하나도 없을 때는 **24h 조건 때문에 막힌 종목 수**와 함께 표시됩니다.
"거래량 급등은 통과했지만 24시간 변동률 때문에 막혔다"는 사실이 구분되어 보입니다.

### RSI 진입 조건

거래량 급등만으로는 **떨어지는 칼을 잡기 쉽습니다**. 그래서 RSI 로 모멘텀을 한 번 더 확인합니다.

```
RSI = 100 − 100 / (1 + avgGain / avgLoss)     ← Wilder 평활법, 1분봉 기준
```

진입 조건: `RSI 하한 ≤ RSI ≤ RSI 상한` (기본 45~75, 기간 14)

- **하한** — 모멘텀이 너무 약하면 진입하지 않음 (하락 추세 차단)
- **상한** — 과매수 구간 진입 금지 (급등 후 반전 위험)
- 진행 중인 1분봉의 현재 종가를 이어 붙여 **실시간 반영**합니다.
- 데이터가 아직 부족해 RSI 를 못 구하면 **막지 않고 통과**시킵니다
  (시드 직후 다른 조건을 만족한 종목을 불필요하게 배제하지 않기 위함)
- 후보 점수에 **범위 중앙 근접 보너스**가 붙어, 적당히 강한 종목이 우선됩니다

> 실제로 확인한 사례 — ETH가 거래량 **42배** 급등(z=38)이어도 RSI 8.2(과매도)라
> 진입이 차단됐습니다. 거래량 조건만으로는 이 종목을 사게 됩니다.

### 손익 판정

```
손익률 = (현재가 − 진입가) / 진입가

손익률 ≥ +10%  → 익절 매도
손익률 ≤ −5%   → 손절 매도
보유시간 ≥ N분  → 시간 청산 (time-stop)
트레일링 스탑 하회 → 청산 (설정 시)
```

- **진입가** = 매수 시 매수호가 + 슬리피지
- **청산가** = 매도 시 매도호가 − 슬리피지
- 판정·체결 모두 **매도호가(bid)** 기준이라 기준선을 넘긴 다음 틱에 체결됩니다.
  (손절선이 −5%인데 −5.1%에 청산되는 게 정상입니다)
- 청산 사유는 `익절 / 손절 / 트레일링 / 시간만료 / 수동` 으로 구분되어 내역에 기록됩니다.

## 실거래 (API 키 연결)

헤더의 **「계정 · 실거래」** 버튼에서 바이낸스 API 키를 넣으면 실제 주문을 넣을 수 있습니다.

### 안전장치 (기본으로 켜져 있음)

| 장치 | 동작 |
|---|---|
| **테스트넷 기본** | 기본 연결 대상은 `testnet.binancefuture.com` (가상 자금) |
| **시크릿 비노출** | API Secret 은 서버 파일(권한 600)에만 있고 화면에 다시 나타나지 않습니다 |
| **재시작 시 자동 해제** | 서버를 재시작하면 실거래 모드가 자동으로 해제됩니다 → 의도치 않은 자동 매수 방지 |
| **실거래는 이중 확인** | 「실거래」 를 직접 입력해야 전환됩니다 |
| **거래 권한만 요구** | 출금(Withdraw) 권한은 필요 없고, 이 프로그램도 출금 API를 쓰지 않습니다 |
| **거래소 규격 사전 검증** | 최소 수량/주문금액 위반을 거래소에 보내기 전에 차단합니다 |
| **포지션 동기화** | 거래소에서 직접 청산/변경한 내용을 20초 간격으로 반영합니다 |

### 사용 순서

1. **테스트넷 키 발급** — [testnet.binancefuture.com](https://testnet.binancefuture.com) 에서 테스트넷 계정 생성 후 API 키 생성
2. 계정 화면에서 **테스트넷** 선택 → 키/시크릿 입력 → 「연결 확인」 (저장 없이 통신만 테스트)
3. 「키 저장」
4. 「가상 모드로 연결」 — 잔고·포지션을 조회하되 주문은 여전히 가상
5. 충분히 검증한 뒤 「실거래 모드로 전환」 (「실거래」 입력 필요)

### 모드 선택

계정 화면의 「거래 모드」 에서 3가지 중 하나를 고릅니다. 헤더 배지가 현재 모드를 항상 보여줍니다.

| 모드 | 잔고/규격 | 실제 주문 | 확인 절차 |
|---|---|---|---|
| **가상 모드** | 설정값 | ❌ | 불필요 |
| **주문 시뮬레이션** | **실제 계정** | ❌ | 불필요 |
| **실거래** | **실제 계정** | ✅ | `실거래` 입력 필요 |

**주문 시뮬레이션 모드**가 핵심입니다. 실제 API 키·실제 잔고·실제 거래 규격
(`stepSize`, `minNotional`)으로 모든 판단이 동작하지만, 거래소로 주문은
전송되지 않습니다. 다음을 손실 없이 검증할 수 있습니다.

- 실제 계정의 잔고·포지션 동기화
- 실제 거래 규격에 대한 주문 가능 여부 (최소 수량/주문금액)
- 급등 감지 → 진입 → 익절/손절 → 청산 전 과정
- 설정된 자본이 실거래에 충분한지

검증이 끝나면 실거래 모드에서 스위치 하나로 주문 전송을 켜면 됩니다.
연결을 끊지 않고 전환되므로 재연결 비용이 없습니다.

### 모드 비교

| | 가상 | 주문 시뮬레이션 | 실거래 |
|---|---|---|---|
| 주문 | 없음 | **없음** | 시장가 전송 |
| 잔고 | 설정 초기 자본 | 실제 지갑 | 실제 지갑 |
| 거래 규격 | 미사용 | **실제 규격** | 실제 규격 |
| 진입가 | 호가+슬리피지 | 참고가 | 실제 체결가 |
| 포지션 동기화 | 불필요 | 수행 | 수행 |
| 헤더 배지 | `가상` | `시뮬레이션` | `실거래`/`테스트넷` |

> 실거래 모드에서도 **익절/손절/RSI/최대 보유 시간/24h 변동 판정 로직은
> 가상 모드와 같은 코드를 그대로 씁니다.** 거래 로직이 갈라지지 않으므로
> 가상 모드에서 검증한 결과가 그대로 유효합니다.

### 주의사항

- 주문은 **시장가(마켓)** 입니다. 체결 가격이 설정한 슬리피지와 다를 수 있습니다.
- 실거래 모드 진입 시 **로컬 포지션을 비우고** 거래소 포지션을 불러옵니다.
- 이 프로그램은 **롱 전용** 전략입니다 (숏 진입 없음). Hedge 모드 계좌에서도 LONG 포지션만 청산합니다.
- 지갑 잔고는 있는데 가용 잔고가 0으로 보이면 거래소의 크로스 마진 설정을 확인하세요.
- 실거래·시뮬레이션 모두 **서버 재시작 시 자동 해제**됩니다.

## 화면 구성

- **헤더** — 총 자산 / 총 손익 / 평가 손익 / 실현 손익 / 현금 / 최대 낙폭, 피드 상태
- **실시간 가격 차트** — 선택 종목의 분봉 + 실시간 가격, 익절·손절 기준선
- **거래량 급등 후보** — 급등 배수, z-score, **RSI 게이지**, 거래량 추이 바, 분당 pace, 수동 매수
- **보유 포지션** — 손익률, 익절/손절 진행률 바, 보유 시간 + **최대 보유 시간 카운트다운**, 수동 매도
- **청산 내역** — 사유(익절/손절/트레일링/시간/수동)별 거래 로그
- **운용 요약** — 현재 적용 중인 조건과 데이터 소스

후보가 없으면 **"조금만 더 느슨해지면 진입할 종목"** 이 뜨면서 어떤 조건에 걸렸는지
(예: `RSI 8.2 범위 밖 (45~75)`) 알려줍니다. 임계값을 튜닝할 때 유용합니다.

거래가 발생하면 우측 하단에 토스트 알림이 뜹니다.

## 주의사항

- **투자 자문이 아닙니다.** 과거 거래량 급등이 이후 수익을 보장하지 않습니다.
- **기본은 가상 모드**입니다. 실거래는 계정 화면에서 명시적으로 전환해야 하며,
  서버를 재시작하면 자동으로 해제됩니다.
- 실거래를 사용할 경우 **반드시 테스트넷에서 먼저 충분히 검증**하세요.
  테스트넷에서 동작했다고 실계정에서도 동일하게 동작한다고 보장할 수는 없습니다
  (호가 두께, 슬리피지, 거래량 구조가 다릅니다).
- 바이낸스 공개 API 호출 제한을 고려해 폴링 주기를 조절했습니다. 동시 요청이 많으면
  `히스토리 추적 종목 수`를 줄이거나 갱신 주기를 늘리세요.

### 참고: 일부 환경에서 WS 스트림이 응답하지 않을 수 있습니다

바이낸스 선물 WebSocket 중 `@aggTrade`, `!ticker@arr`, `@kline_1m` 는
일부 네트워크 환경에서 **handshake 는 성공하지만 데이터를 전혀 보내지 않는** 경우가 있습니다.

그래서 이 프로그램은:
- 실시간 가격을 `@bookTicker` → `@trade` → REST 순서로 **자동 대체**하고
  현재 사용 중인 소스를 우측 패널에 표시합니다.
- 거래량은 24시간 누적 거래대금의 차분이 아니라 **1분봉을 직접 폴링**해 계산합니다.
  (24시간 값은 롤오버로 인해 차분이 음수가 될 수 있어 근사가 불가능합니다)
